BSignal Detection Algorithms

All core detection functions live in worker/src/ebp-worker.js. In all functions, bar0 = newest/current bar, bar1 = prior bar.

EBP Detection — detectEBP(candles)

Engulfing Body Pattern: the current bar sweeps the prior bar's extreme and closes beyond the prior bar's body.

prevBodyHigh = Math.max(bar1.open, bar1.close)
prevBodyLow  = Math.min(bar1.open, bar1.close)

bullEBP = bar0.low  < bar1.low  && bar0.close > prevBodyHigh
bearEBP = bar0.high > bar1.high && bar0.close < prevBodyLow

Returns: { direction, candleTime: bar0.time, sweptLevel, closedLevel: bar0.close }
  sweptLevel = bar1.low  (bull) | bar1.high (bear)

Sweep Detection — detectSweep(candles)

Bar sweeps prior extreme but closes back inside the prior bar's range.

bullSweep = bar0.low  < bar1.low  && bar0.close > bar1.low
bearSweep = bar0.high > bar1.high && bar0.close < bar1.high

Returns: { direction, candleTime, sweptLevel,
           closedInsideLevel: bar0.close, prevHigh: bar1.high, prevLow: bar1.low }

FVG Detection — detectFVG(candles)

Oldest-first array. Gap assessed between barIMinus2 (candles[n-3]) and barI (candles[n-1]), skipping middle bar.

bullish: barIMinus2.high < barI.low
  top    = barI.low
  bottom = barIMinus2.high

bearish: barIMinus2.low > barI.high
  top    = barIMinus2.low
  bottom = barI.high

midpoint   = (top + bottom) / 2
formed_at  = barI.time          (epoch ms)
expires_at = formed_at + 14 * 24 * 60 * 60 * 1000   (14-day TTL)

FVG Mitigation Rules — checkFVGMitigation(bar, fvgRow, rule)

RuleBullish TriggerBearish Trigger
'50_percent' (default)bar.close < fvgRow.midpointbar.close > fvgRow.midpoint
'any_touch'bar.close <= fvgRow.topbar.close >= fvgRow.bottom
'full_fill'bar.close < fvgRow.bottombar.close > fvgRow.top

isPriceInFVG(price, fvgRow): price >= fvgRow.bottom && price <= fvgRow.top

FVG Zone Processing — processFVGZones(db, table, symbol, tf, candlesOldestFirst, latestBar)

  1. Calls detectFVG on candlesOldestFirst.
  2. INSERT OR IGNORE into table (prevents duplicate/overlapping zone via unique index).
  3. Sweeps all active=1 FVG rows for the symbol+TF, calls checkFVGMitigation on latestBar.
  4. Sets active=0, mitigated_at=now, mitigation_rule on mitigated rows.

MSS Detection — detectMSS(bar, swingState)

Market Structure Shift. Requires run_candle_count >= 3.

If run_dir = 'bearish' && bar.close > last_confirmed_swing_high → bullish MSS
If run_dir = 'bullish' && bar.close < last_confirmed_swing_low → bearish MSS

Swing State Machine — updateSwingState(db, table, symbol, tf, candlesOldestFirst)

ATR(14)-based doji threshold (fallback = (bar.high - bar.low) * 0.1). State stored in swing_states / nse_swing_states via INSERT OR REPLACE.

StateTransitionAction
null (bootstrap)prevBar comparisonSet initial run_dir from first two bars
bullish runClose < pending_swing_highConfirm swing high → track pending_swing_low
bearish runClose > pending_swing_lowConfirm swing low → track pending_swing_high
anyMSS detectedFlip run_dir, clear pending swings, reset run_candle_count=1

TTrades Closure Bias — calcTTradesBias({bar1, bar2})

Determines the HTF directional bias from a single two-bar comparison. bar1=prior, bar2=current. closePos = (c0-l0)/(h0-l0)*100; defaults to 50 if range==0.

CodeConditionTypeBias
outsideDh0>prevH && l0<prevLoutside_barbullish if closePos≥50, else bearish
insideDh0<=prevH && l0>=prevLinside_barneutral
sweptHh0>prevH && c0<=prevHswept_high_closed_insidebearish
sweptLl0<prevL && c0>=prevLswept_low_closed_insidebullish
aboveHc0>prevHabove_prev_highbullish
belowLc0<prevLbelow_prev_lowbearish
else—noneneutral

Priority order: outsideD → insideD → sweptH → sweptL → aboveH → belowL → else. Note: sweptH and sweptL only reached if not outside_bar; aboveH/belowL only if not swept.

Daily Candle Time Reconstruction

In ebp-worker, getDailyCandlesFromCache reads LIMIT 5, newest-first, and reconstructs bar.time = nyDateAtHourToUTCms(dateStr - 1 day, 17). This sets the candle open time to 17:00 NY of the prior calendar day — the standard 17:00 NY trading-day boundary.

nyDateAtHourToUTCms(dateStr, hour): converts NY wall-clock date+hour to UTC ms, DST-aware via Intl short-offset method.

CT1–T4 Chain State Machines

Chain state lives in the chain_state table. Initiation happens in ebp-worker.js; advancement happens in sweep-cron.js (processTemplateChains).

T1 — HTF EBP → LTF FVG Entry
  • Initiated by HTF EBP signal
  • Initial state: 'awaiting_fvg_entry'
  • Expiry: endOfUTCMonthISO()
  • HTF candle body not stored
  • Completes when LTF FVG is active AND close is inside FVG
T2 — HTF EBP → LTF Retracement FVG
  • Initiated by HTF EBP signal
  • Initial state: 'awaiting_retracement'
  • Stores htf_candle_open, htf_candle_close, htf_candle_open_time, htf_candle_close_time
  • Expiry: endOfUTCMonthISO()
  • FVG must form within HTF EBP candle time window AND fvg.top <= bodyTop && fvg.bottom >= bodyBottom
T3 — HTF EBP → LTF Sweep → LTF MSS
  • Initiated by HTF EBP signal → initiateT3Chain
  • Initial state: 'awaiting_sweep'
  • Expiry: Date.now() + windowMins * 60 * 1000
  • Step 2 (sweep): state→'awaiting_mss' via advanceT3Chain
  • Step 3 (MSS, if step3_enabled=1): state→'complete' via completeT3Chain
  • If step3_enabled=0: chain completes at Step 2 (sweep alone)
T4 — LTF Sweep → LTF FVG Entry
  • Initiated by sweep detection in processTemplateChains (no HTF EBP required)
  • Initial state: 'awaiting_fvg_entry'
  • Stored with htf=''
  • Expiry: endOfUTCMonthISO()
  • Completes same as T1 via checkFvgEntryChain

Chain Advancement Logic

checkFvgEntryChain(env, chain, latestClose)

Applies to T1, T2, T4 (state 'awaiting_fvg_entry' or 'awaiting_retracement'):

  1. Fetches all active FVGs for chain.symbol, chain.ltf, chain.direction
  2. For T2: filters to FVGs where formed_at ∈ [htf_candle_open_time, htf_candle_close_time] AND fvg.top <= bodyTop && fvg.bottom >= bodyBottom
  3. Reads per-template fvg_rule from user_templates
  4. Calls checkFVGMitigation(latestBar, fvg, rule) — if mitigated, skip
  5. Calls isPriceInFVG(latestClose, fvg) — returns matching FVG row or null

completeFvgEntryChain(db, chainId, signalId, fvgId)

Sets step2_signal_id and fvg_id on the chain record.

Heatmap Calculation

pct(pair) = (close - open) / open * 100
heatmap[base][quote] = +pct
heatmap[quote][base] = -pct

Result: symmetric 8×8 matrix where each cell [A][B] shows A's gain relative to B.

Strength Score

Per currency: mean of all heatmap values for that currency (across all 7 cross-pair partners). Higher = stronger relative performance in that 1H bar.

Pearson Correlation — pearsonCorr(a, b)

Standard Pearson on min(a.length, b.length) points. Applied to 10-candle return series per currency. 8×8 matrix written to market_breadth_correlation.

Weekly Breadth — computeWeeklyBreadth(env, debugLog)

  1. Reads last 35 days of market_breadth_intraday
  2. Groups by ISO week (Thursday-anchor)
  3. Most recent completed week: Sunday endDate < today, requires ≥3 distinct trading days → averages per-currency strength → writes market_breadth_cache tf='1W'
  4. Current in-progress week (no minimum threshold) → writes tf='1W_current'
  5. Both weekly rows have heatmap='{}' (no pair-level data from intraday aggregation)

Forex Weekend Gate

isForexClosedWindow(nowMs): day===6 (all Saturday) OR (day===5 AND hour≥17) (Friday after 17:00 NY) OR (day===0 AND hour<17) (Sunday before 17:00 NY). Breadth cron skips computation during closed window.

Data Retention

market_breadth_intraday: pruned >40 days. Cache: INSERT OR REPLACE on each run.

Frontend Display

In MarketBreadthPage.jsx: 60s poll for intraday, 4h poll for weekly. getCurrentSessionStart() uses NY 5PM rollover. Three recharts visualizations:

  • Daily: dual-bar (today + yesterday) with DeltaLabel SVG custom label

GDXY Synthesis

Implemented in watchdog-worker/src/index.js. Synthetic DXY derived from 6 ICE constituent pairs, stored in dxy_candle_cache, then mirrored to candle_cache as symbol='DXY'.

ICE Formula

DXY_CONSTITUENTS = ['EUR/USD','USD/JPY','GBP/USD','USD/CAD','USD/SEK','USD/CHF']
DXY_WEIGHTS = {
  'EUR/USD': -0.576,   // largest negative weight (EUR dominant)
  'USD/JPY': +0.136,
  'GBP/USD': -0.119,
  'USD/CAD': +0.091,
  'USD/SEK': +0.042,
  'USD/CHF': +0.036
}
DXY_K = 50.14348112

DXY = K × PROD( constituent ^ weight )

For HIGH candle value:
  Negative-weight pair HIGH → use pair's LOW (negative weight pulls DXY down when pair is high)
  Positive-weight pair HIGH → use pair's HIGH
For LOW candle value: reverse
open/close: use pair's open/close directly

Functions

computeDXYCandle(candlesBySymbol, time)

Assembles one DXY OHLC bar from all 6 constituents at a given timestamp. Returns null if any constituent is missing at that time.

computeSyntheticDXY(env)

Reads json_extract(candles_json,'$[0]') from yahoo_candle_cache per constituent. Checks all are time-aligned. INSERT OR IGNORE into dxy_candle_cache tf='1H'.

seedDXYHistory(env)

Runs only when dxy_candle_cache.COUNT=0. Finds common timestamps across all 6 constituents, inserts all common 1H candles. Then derives 4H/Daily/Weekly chains from the seeded data.

Higher-Timeframe Derivation

synthesiseDXY4H(db):
  Last 4×1H rows newest-first → 4H candle
  time  = oldest candle time (open time of first 1H bar in group)
  open  = oldest bar's open
  high  = max of 4 highs
  low   = min of 4 lows
  close = newest bar's close
  INSERT OR IGNORE into dxy_candle_cache tf='4H'

synthesiseDXYDaily(db):
  tradingDayOpenMs = now - 24h
  Reads 1H rows WHERE candle_time >= tradingDayOpenMs ORDER BY ASC
  Requires >= 20 rows
  INSERT OR IGNORE tf='Daily'

synthesiseDXYWeekly(db):
  Last 5 Daily rows → reversed to oldest-first → same OHLC synthesis
  INSERT OR IGNORE tf='Weekly'

writeDXYBlobsToCache(db, tfs, limit=50)

Mirrors dxy_candle_cache rows into candle_cache as symbol='DXY' per TF. candles_json is the array of last limit rows (newest-first).

Execution Sequence in handleBreadthFetchCron

  1. fetchBreadthFromYahoo(BREADTH_SYMBOLS) — all 29 pairs in parallel
  2. seedDXYHistory(env) — if dxy_candle_cache empty
  3. computeSyntheticDXY(env)
  4. If 4H boundary: synthesiseDXY4H + writeDXYBlobsToCache(['4H'])

  6. If nyHour==17 && nyDay==5: synthesiseDXYWeekly + writeDXYBlobsToCache(['Weekly'])

Bugs & Inconsistencies

step2_signal_id never populated for T1/T2/T4
chain_state.step2_signal_id column exists and is set by completeFvgEntryChain, but ChainProgressBar.jsx notes this is never actually populated in practice for T1, T2, or T4 chains. T3 sets it correctly.
/upgrade route not defined
ExpiryBanner.jsx navigates to /upgrade when user clicks "Renew". This route does not exist in App.jsx. Users clicking Renew will hit a 404/no-match route.
nse_sma_state.updated_at type mismatch
Column declared with INTEGER affinity in schema (legacy declaration), but workers write it via toISOString() producing a TEXT value. SQLite stores the text correctly due to flexible typing, but the declared affinity is incorrect.
nse_candle_cache.updated_at vs forex timestamps
NSE candle cache stores updated_at as INTEGER epoch (seconds). All forex cache tables use TEXT ISO strings. Watchdog health check handles this: it reads NSE field as epoch seconds, not as ISO text.
sweep-worker BIAS_SOURCE.sweep missing M30
In BIAS_SOURCE_FRONTEND.sweep, M30→'4H' is present, but the backend BIAS_SOURCE.sweep in ebp-worker.js shows M5:'1H', M15:'1H', M30:'4H', 1H:'D', 4H:'W'. Frontend mirrors this correctly — no mismatch. (Not a bug, but worth verifying if sweep configs are added for M5.)
getDailyCandlesFromCache LIMIT discrepancy
ebp-worker uses LIMIT 5 (sufficient for EBP detection: 2 bars needed). sweep-worker uses LIMIT 25 (needed for SMA9 computation requiring 9+ daily candles). If sweep-worker ever uses getDailyCandlesFromCache for EBP-style bias detection, it over-fetches.
No auto-reconnect in PriceFeedPanel
WebSocket connection to wss://ws.twelvedata.com has no reconnection logic. If connection drops, feed goes silent until user refreshes.
fetchSignalTF chunk-dropping under key shortage
When chunks.length > keys.length, excess chunks are silently dropped (logged as warning only). Symbols in dropped chunks receive no candle refresh for that TF cycle.
dxy_candle_cache / yahoo_candle_cache absent from schema.sql
Both tables are created ad hoc (likely via D1 console or migration not tracked in the repo). They exist in production but are invisible to schema-based tooling.

Design Gaps

No WebSocket reconnect
PriceFeedPanel opens one WebSocket; if it closes (network hiccup, CF timeout), there is no reconnect loop. Log cap is 20 messages.
T3 step2_signal_id not stored
When T3 advances from sweep to MSS, no intermediate signal ID is stored in chain_state.step2_signal_id. Only the final completion sets the chain record.
Upstox source not selectable in Admin key form
Admin.jsx only offers 'twelvedata' or 'yahoo' as source options when creating API keys. Upstox credentials are managed separately and cannot be added via the same key management UI.
market_breadth_cache weekly rows have empty heatmap

N5CISD — Definition & Watch Lifecycle

Definition

CISD (Change In State of Delivery) is a TTrades concept. In this codebase: the open price of the first candle of the pullback run — i.e. the candle whose time equals swingState.run_start_time when run_dir is opposite to the cloud direction. A bar closing beyond this price signals a character change in delivery: the market has stopped "delivering" against the trend.

Step 2a — Arm Condition

Fires when phase='distribution' and no watch is already active in the same direction. All must hold (bull example):

  • Wicked into cloud: bar0.low < cloudTop && bar0.low > cloudBottom && (cloudTop - bar0.low) >= atr14 × WICK_PENETRATION
  • Rejected: bar0.close > cloudTop
  • Bias gate passes

On arm: cisd_watch_active=1, cisd_watch_direction=trend direction, cisd_pullback_start=swingState.run_start_time (ISO), cisd_watch_armed_at=now ISO.

A fresh rejection in the opposite direction overwrites an existing watch in the other direction.

Step 2b — Confirm Condition

Checked each cron cycle when watch is active (same direction as cloud phase):

  1. Check watch not expired: Date.now() - new Date(watchArmedAt) < WATCH_EXPIRY_MS[tf]
  2. Check bias has not flipped (re-evaluates checkSMABias())
  3. Determine pullbackRunActive: swingState.run_dir === opposite_direction
  4. Read cached candles, filter to c.time >= pullbackStartMs, sort oldest-first
  5. cisdLevel = pullbackCandles[0].open
  6. Bull CISD: bar0.close > cisdLevel · Bear CISD: bar0.close < cisdLevel

MSS Alternative Confirmation

When confirmation_mode='mss' or 'either': mssOk = bar0.close > swingState.last_confirmed_swing_high (bull). In either mode the first of MSS or CISD to trigger fires the alert.

Expiry & Disarm Events

  • Watch timer expired → silently cleared
  • Bias flipped → silently cleared
  • Exhaustion event → cleared regardless
  • Alert fired → cleared; last_signal_time updated; cooldown starts

N8isDuplicateAlert — Actual SQL & Bug Verdict

Section M of this encyclopedia states that isDuplicateAlert "uses new Date().toISOString() as the comparison cutoff directly … making dedup always pass." This is factually incorrect. The verified source (sweep-cron.js lines 320–336) shows the function is working correctly:

async function isDuplicateAlert(db, userId, symbol, tf, direction, alertType) {
  const windowMs = ALERT_INTERVAL_MS[tf] || 60 * 60 * 1000;
  const cutoff = new Date(Date.now() - windowMs).toISOString();  // past timestamp
  const existing = await db.prepare(`
    SELECT id FROM alert_history
    WHERE user_id = ? AND symbol = ? AND timeframe = ?
      AND direction = ? AND alert_type = ? AND fired_at > ?
    LIMIT 1
  `).bind(userId, symbol, tf, direction, alertType, cutoff).first();
  return existing !== null;
}

Correctness Analysis

  • cutoff = now − windowMs — a proper past timestamp, not the current time.
  • fired_at > cutoff — matches alerts fired after the lookback window started, i.e. within the window. Correct semantics.
  • fired_at is TEXT ISO 8601 (post-migration 013). SQLite ISO 8601 string comparison is lexicographically correct for UTC timestamps.
  • Returns true (is duplicate) when a recent alert exists → new alert suppressed. Dedup is working as designed.

    now.getUTCMonth() + 1,   // pass next month…
    0,                        // …day 0 = last day of the current month

  • UTC day-0 trick: Date.UTC(year, month+1, 0) = last day of the current month in UTC. Zero-indexed month means passing getUTCMonth()+1 targets "month index = next month"; day 0 rolls back to end-of-current.
  • Precision: Second-level only. Milliseconds are 0 (ISO string ends :59.000Z).
  • No DST risk: UTC; unaffected by server locale.
  • Used for: T1 (awaiting_fvg_entry) and T2 (awaiting_retracement) expiry. T3 uses rolling window_mins window; T4 also uses endOfUTCMonthISO().
  • Duplication rationale: Cloudflare Workers have no shared module infrastructure across worker packages. The pattern is explicitly acknowledged in the codebase's // SYNC NOTICE comments.
